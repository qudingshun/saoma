# 成品出库（手持 PDA 装柜防错）

运行在 **东集 CRUISE2 安卓工业 PDA（Android 11）** 的离线装柜扫码工具：一柜一档、扫码即校验（串号 / 重复 / 超量）、实时落盘、删除可撤回。

**当前版本：v1.8.1（versionCode 25，数据库 v14）** ｜ 状态：v1.8.1 修复首页「出库扫码」按钮投影压住下一按钮边框；WiFi 同步（局域网，未配对不影响扫码）

## 功能与操作流程

```
首页（成品出库）
 ├─【出库扫码】★主流程
 │   └─ 设置页：柜号 + 计划装柜数量（窄框并列）+ 操作员工号（选填）+ 已扫码数量（只读）
 │        ├─ 计划装柜数量只由人工填写，App 不会自动改写（退出再进入不丢失、不被覆盖）
 │        │    从扫码页返回 → 显示上次设置的计划装柜数量（v1.7.0）
 │        │    选择前面已有的柜号 → 显示该柜前期存的计划装柜数量（v1.7.0）
 │        │    留空且该柜今天已扫码（续装）→ 装柜时按该柜已存计划继续（占位符/黄条可看到计划值）
 │        ├─ 已扫码数量（= 已装柜数量）：与工号栏同款只读框（大小布局一致、数字不可修改），按今天已装正常数自动统计
 │        ├─ 操作员工号：下拉 A / B / C / D 快速选择，或扫工牌/手输（字母+数字、自动大写、≤12 位；记住上次填写）
 │        │    焦点在工号栏时扫码键填入工号（替换）；焦点在其余位置时填入规则栏（原行为）
 │        ├─ 规则录入：扫真码自动填入（人工删减成前缀）/ 手动录入 / 从规则库选择（多选）
 │        ├─ 录入规则可填「流水号最小值 / 最大值」：前缀后的数字须落在范围内，超范围报串号（留空 = 该侧不限）
 │        ├─ 流水号不在前缀后整段时：再填「末尾位数」N（如 3）→ 取条码最后 N 位数字核对（末尾符号/字母忽略），
 │        │    例：ASV12SDFWG05455056$，前缀 ASV12、末尾 3 位 → 核对 056
 │        ├─ 规则行点「设范围 / 流水 …」可补录 / 修改 / 清除范围（从规则库导入的规则同样可设）
 │        ├─ 每条规则可勾：可重复扫（双码机固定码）/ 计入统计（不勾 = 辅助码，只留痕不计数）/ 查历史串号 /
 │        │    忽略（仅「可重复扫」时生效：扫到不记录、不落盘、不计数，语音仍播报「辅助码」）
 │        ├─ 同柜号「今天」已有装柜记录（不含已删除）→ 自动载入原规则 + 黄条显示已扫码件数
 │        │    → 继续扫码接着计数，扫满计划弹完成（已装齐再进入 → 提示超量；补装改大计划）
 │        ├─【装柜】固定在按钮区；「本柜条码规则」列表已移到【装柜】按钮下方（固定区域内部滚动，不影响上方设置排版）
 │        └─【装柜】→ 扫码页
 │             ├─ 输出格式：【柜号，条码】大字；计数卡：正常/串号/重复/超量；计划装柜数量与已扫码数量分列展示（有工号时同排显示操作员）
 │             ├─ 每扫一码：入库 + TSV 落盘（实时 ✓/⚠）+ 报警反馈（正常 / 非正常分别设置声音开关与震动强度：关/弱/中/强）
 │             ├─ 语音朗读（可关，默认开）：正常扫一码读「已扫码，N」（自然读法：25 → 二十五）；辅助码 / 忽略读「辅助码」
 │             ├─ 已扫码数量扫满计划装柜数量 → 弹「装柜完成」并追加一行到装柜完成汇总（返回设置后规则清空；该柜号当天再进入再扫提示超量）
 │             ├─ 报警三重编码：颜色 + 图标 + 文字同现（计数卡 / 报警弹窗 / 记录行 / 最新输出）
 │             ├─ 记录删除：重复/串号/辅助码/超量一步确认；正常记录三步确认（均进回收站）
 │             ├─ 撤回 / 前进：本柜操作栈（撤销扫码 / 恢复删除，上限 100 步）
 │             └─【返回设置】柜号 / 计划装柜数量 / 规则原样保留（已扫码数量同步展示）；从首页进入则为整页空白
 ├─【继续装柜：柜号】快捷入口（最近有扫码记录时出现）：一键带出最近柜号，自动载入原规则 + 已扫码数量
 ├─【扫码记录查看】按「日期 + 柜号」聚合（两级）；单组 / 本日 / 批量删除（三步确认）
 │    └─ 长按本页标题「扫码记录」进「回收站」：逐条 / 全部撤回、清空（三次确认）
 └─【规则库】以型号为组维护：先「新增型号」，再在型号行「＋ 添加规则」逐个添加前缀（列表默认折叠，只显示型号名）；
      每条规则可设 可重复扫 / 计入统计 / 查历史串号 / 忽略；供设置页多选（选择弹窗以型号名称为主显示）
      导入 / 导出 XLSX（型号名称 / 前缀 / 四个开关），便于拷到其他 PDA 维护
```

## 校验与报警逻辑（出库扫码）

校验顺序：**规则前缀（串号）→ 同柜重复 → 查历史串号 → 辅助码 → 超量 → 正常**

| 情况 | 结果 | 反馈 |
|---|---|---|
| 条码不以任何规则前缀开头，或流水号超出该规则的最小/最大值（含「末尾 N 位」模式下取出的末尾 N 位数字） | 串号 SERIAL_MISMATCH | 红屏 + 蜂鸣 + 循环振动 |
| 同柜已扫过的条码（该规则未勾「可重复扫」） | 重复 DUPLICATE | 红屏 + 蜂鸣 + 循环振动 |
| 勾「查历史串号」的规则：条码已在其他柜记录里出现过 | 串号 SERIAL_MISMATCH | 红屏 + 蜂鸣 + 循环振动；提示"已于 xx 在柜 xxx 录入过" |
| 命中「不计入统计」规则的条码 | 辅助 AUX | 蓝屏 + 嘀声，只留痕不计数（可反复扫） |
| 勾「可重复扫」+「忽略」的规则：扫到该条码 | 忽略（按辅助码反馈） | 蓝屏 + 嘀声 + 语音「辅助码」；**不记录、不落盘、不计数**（双码机固定码减噪） |
| 已扫码正常数 ≥ 计划装柜数量 | 超量 OVER_LIMIT | 黄屏 + 提示音 + 循环振动 |
| 正常（计入统计的规则） | OK | 绿屏 + 嘀声，计数 +1 |

- 报警弹窗（重复 / 串号 / 超量）：点确认停止报警；重复 / 串号 / 超量弹窗还可一步删除该条
- 震动和声音设置（扫码页【震动和声音设置】，v1.7.0 由「报警设置」升级）：正常扫码 / 非正常扫码（串号·重复·超量）两组各自可设「声音开关」+「震动强度（关 / 弱 / 中 / 强）」；升级时沿用旧开关作为默认值。两者都关 = 仅界面提示（颜色 + 图标 + 弹窗文字）
- 语音朗读（同一弹窗内开关，默认开）：正常扫码读「已扫码，N」（自然读法：10 → 十、25 → 二十五、110 → 一百一十、256 → 二百五十六、300 → 三百）；辅助码 / 忽略读「辅助码」；重复 / 串号 / 超量不朗读（由报警声与界面提示负责）
- 报警停止：弹窗确认 / 任意触屏 / 扫下一枪 / 删除记录 / 离开扫码页，另有 10 秒兜底自动停
- 报警三重编码：每种结果都同时有「颜色 + 图标 + 文字」（计数卡 ✓/⚠/↻/⊕、报警弹窗标题、记录行标签、最新输出），不只靠颜色区分
- **计数口径**：正常 / 串号 / 重复 / 超量均按「今天」（设备本地日期）统计；已删除记录与「忽略」的条码不参与；跨天再装不继承昨天计数

## 删除 / 撤回 / 回收站

- 删除一律**软删除**（`scan_records.deletedAt`），清空回收站前都可恢复
- 确认分级：重复 / 串号 / 辅助码 / 超量 = 1 步；**正常记录 = 3 步**；记录页单组 / 本日 / 批量 = 3 步；清空回收站 = 3 步
- 扫码页「撤回 / 前进」：撤销上一枪（软删）/ 恢复删除；换柜自动清空操作栈
- 回收站（记录页长按标题进入）：逐条撤回 / 全部撤回（恢复后重新计入统计）；清空 = 永久删除
- 落盘文件与 App 动作同步：整组删空 → 文件从「装柜记录」挪到「回收站」目录；撤回 → 挪回；部分删除 → 两侧各留一份

## 自动落盘（TSV）

- 路径：`/sdcard/ZhuangGui/装柜记录/yyyy-MM-dd/柜号.tsv`（按日期分目录、按柜号分文件；已删除的进 `/sdcard/ZhuangGui/回收站/`）
- 列（Tab 分隔）：`时间 ⇥ 柜号 ⇥ 条码 ⇥ 完整码 ⇥ 结果 ⇥ 操作员`（结果 = 正常/串号/重复/超量/辅助；操作员 = 设置页填写/扫入的工号，未填为空）
- 装柜完成汇总：`/sdcard/ZhuangGui/装柜完成汇总.tsv`（单文件累积，每装齐一柜追加一行；列：`完成时间 ⇥ 柜号 ⇥ 计划数量 ⇥ 正常 ⇥ 串号 ⇥ 重复 ⇥ 超量 ⇥ 记录总数 ⇥ 操作员`，计划数量 0 = 不限）
- UTF-8 带 BOM（Excel 打开中文不乱码）；同柜号回来继续追加；**每扫一码立即写入**
- 权限：Android 11+ 需「所有文件访问」（`MANAGE_EXTERNAL_STORAGE`，首次点【出库扫码】自动引导授权）
- v1.5.0 之前的旧 .csv 文件：同步时自动挪进文件回收站归档，不再参与新逻辑

## 扫码对接（设备端配置，实机验证可用）

- 解码由系统「扫描工具」（`com.seuic.scanner.activity`）完成——**不要禁用/停用它**（禁用 = 完全不能扫码）
- 系统「扫描配置」→ 应用扫描配置 → 已配置应用（**按包名生效，重装 App 不丢失**）：

| 配置项 | 值 |
|---|---|
| 选择应用 | 成品出库（com.zhuanggui.pda） |
| 条码发送方式 | 广播 |
| 广播名称 | `com.android.server.scannerservice.broadcast` |
| 键值（extra） | `scannerdata` |
| 结束符 | ENTER |

实机链路：物理扳机 → 系统解码 → 广播送达 → App 收码 → 界面反馈 + TSV 落盘（全通）

App 端兼容（`scan/ScannerManager.kt`，换机型只改这两个列表，新值放第一优先）：
- 监听动作：`com.android.server.scannerservice.broadcast`｜`android.intent.action.SCANRESULT`｜`android.intent.action.BARCODE_CAPTURE`｜`urovo.rcv.message`｜`com.android.scanbroadcast.SCAN`
- extra 键名：`scannerdata`｜`value`｜`barcode`｜`barcode_value`｜`scan_value`｜`data`｜`result`｜`BarcodeStr`
- 兜底：扫码页 HID 键盘模拟录入框（`HidScanField.kt`）；**同一时间只开一种输出**——广播 + 键盘双开会让同一枪产生两份数据
- 广播来源无法校验（系统限制，审计 13）：接受为已知限制，App 收到即记 Log 留痕（`adb logcat -s ScannerManager` 可见条码内容）

收不到码排查：①「扫描配置 → 已配置应用」里配置是否还在；②App 是否在前台（或进程存活）；③`adb logcat -s ScannerManager`（系统服务偶发刷屏会挤掉日志，此时用 `adb logcat --pid <App进程号>` 过滤更稳）

常用调试命令：

```
adb logcat -s ScannerManager                                        # App 收码日志（很少收到时换按 PID 过滤）
adb shell pidof com.zhuanggui.pda                                   # 查 App 进程号
adb logcat --pid <进程号>                                            # 按进程过滤日志（系统服务刷屏时最稳）
adb shell am broadcast -a com.android.server.scannerservice.broadcast --es scannerdata "TEST123"   # 模拟扫码广播
adb install -r app\build\outputs\apk\debug\app-debug.apk            # 覆盖安装（数据不丢）
```

## 规则源导入 / 导出（XLSX）

- 导出格式（推荐）：`型号名称 | 前缀 | 可重复扫 | 计入统计 | 查历史串号 | 忽略`（是/否）
  - 每个型号可有多行（多个前缀）；空型号也导出为一行（前缀留空），导入时用于建空型号
  - 路径：`/sdcard/ZhuangGui/规则库/规则库_yyyyMMdd_HHmmss.xlsx`（列宽已设置、首行冻结）
- 导入：支持 .xlsx / .xls / .csv / .txt / .tsv
  - 新 XLSX 按表头自动识别「型号名称在前」；旧文件（前缀在第一列）继续兼容
  - 只有型号、没有前缀的行 = 建空型号
  - 首行表头（型号名称/前缀/条码/barcode 等）自动跳过；前缀去空格转大写；同前缀去重
  - 回导 = 覆盖更新（按前缀）：带开关列的导出文件以文件为准；两列旧文件覆盖时保留库内原开关
- 导入的规则默认「不可重复扫 + 计入统计 + 不查历史 + 不忽略」；需要双码机/辅助码等设置时，导入后在规则库点「编辑」勾选
- v1.7.5：规则库改为「型号优先」维护（先建型号，再逐个添加规则；列表按型号折叠显示）

## 已知现象与注意事项

- 覆盖安装 = 应用进程重启（界面状态清空），**数据不丢**；卸载重装会清空 App 数据库，但 `/sdcard/ZhuangGui/` 下的文件不受影响
- 仪器化测试 `connectedDebugAndroidTest` 跑完默认会卸载 App（清空数据库）——已在 `gradle.properties` 加 `android.injected.androidTest.leaveApksInstalledAfterRun=true` 保留安装；若曾误卸载，可用跑前快照经 `run-as` 回灌 `databases/zhuanggui.db` 恢复
- 冷启动约 4~7 秒（PDA 性能所限）
- 偶尔系统残留 "Application Error" 残影窗口（旧进程痕迹）：重启设备即消失，不影响使用
- 扫码触发以物理扳机为准：机内「扫描」软触发按钮经真机验证在 CRUISE2 上无效（4 个候选广播全无响应；东集触发走绑定服务、无广播通道），已从界面移除（审计 15）；如未来要软触发需集成东集 SDK 绑定 ScanService
- 语音朗读使用 App 内置中文语音片段（assets/voice，16kHz PCM），**不依赖系统 TTS 引擎**（现场机无语音引擎也可用）；数字按自然读法拼接（10 → 十、25 → 二十五、105 → 一百零五、256 → 二百五十六，超过 999 退回逐位）；可在「震动和声音设置」开关，关闭后不再播报，不影响扫码、报警声与落盘
