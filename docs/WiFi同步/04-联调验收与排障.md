# WiFi 同步方案 · 04 联调验收与排障

---

## 1. 联调顺序（**严格按此顺序，不要跳**）

```
① PC 服务能起  →  ② 本机能访问  →  ③ 局域网能访问  →  ④ PDA 能访问  →  ⑤ 才写同步代码
```

**每一步用浏览器/curl 验完再进下一步**，否则出问题时根本分不清是网络还是代码。

---

## 2. 逐阶段验收

### ② PC 本机

```powershell
curl.exe http://127.0.0.1:8000/api/v1/health
```
期望：`{"ok":true,"serverVer":1,...}`

### ③ 局域网可达（关键一步）

先拿 IP：

```powershell
ipconfig | Select-String "IPv4"
```

再验（换成你的 IP）：

```powershell
curl.exe http://192.168.1.100:8000/api/v1/health
```

失败 → 看 §3 排障表 `R1 / R2`。

### ④ PDA 能访问

PDA 上开**浏览器**（不是 App）访问同一个地址：

```
http://192.168.1.100:8000/api/v1/health
```

- 能看到 JSON → 网络通了，可以开始做 App 侧
- 打不开 → 别急着改代码，先解网络（§3 `R1`–`R5`）

### ⑤ App 侧契约自测（不依赖界面）

用 curl 模拟 PDA 的两个核心动作：

```powershell
# 拉任务
curl.exe -H "X-Sync-Token: K7F2QW9M" -H "X-Device-Id: PDA-TEST" `
  "http://127.0.0.1:8000/api/v1/tasks?since=0"

# 推一条扫码记录（注意 uid 固定，重发应返回 duplicated=1）
curl.exe -X POST -H "Content-Type: application/json" -H "X-Sync-Token: K7F2QW9M" `
  -d "{\"deviceId\":\"PDA-TEST\",\"scans\":[{\"uid\":\"t-001\",\"containerNo\":\"TEST123\",\"barcode\":\"ASV12001\",\"fullCode\":\"TEST123，ASV12001\",\"result\":\"OK\",\"scannedAt\":\"2026-10-20T15:01:02.123+08:00\",\"operatorId\":\"A\",\"deletedAt\":null}]}" `
  http://127.0.0.1:8000/api/v1/scans
```

**幂等验收**：把上面这条 `POST /scans` **重复执行 3 次** —— 第 1 次 `accepted:1`，第 2、3 次 `duplicated:1, accepted:0`，`GET /scans` 里始终只有 1 条。这就是"重传不翻倍"。

## 3. 排障对照表

| 编号 | 症状 | 最可能原因 | 处理 |
| --- | --- | --- | --- |
| **R1** | 本机 `127.0.0.1` 能访问，局域网 IP 不能 | Windows 防火墙拦 | 加 8000 入站规则；确认网络配置文件是"专用"而非"公用" |
| **R2** | 规则已加仍不通 | 规则只对 `Private` 生效，但网络是 `Public` | 网络设置改为专用，或规则 `-Profile Any` |
| **R3** | PDA 打不开，电脑能打开自己 | **路由器开了 AP 隔离** | 路由器后台关掉「AP 隔离/客户端隔离」 |
| **R4** | 昨天能连，今天不行 | PC 的 IP 变了（DHCP） | 路由器做 DHCP 保留；或重新扫配对码 |
| **R5** | 完全不通但 IP/防火墙都对 | 手机连的是**蜂窝网**不是 WiFi | 关移动数据；或确认连的是同一个 WiFi |
| **R6** | 服务启动报 `address already in use` | 端口被占（旧进程/别的程序） | `netstat -ano \| findstr :8000` → 结束进程，或换端口 |
| **R7** | App 报 `CLEARTEXT communication not permitted` | 缺少 `network_security_config.xml` 或没在 Manifest 引用 | 见 `02-PAD端实施步骤.md` §7 |
| **R8** | App 报 401 | token 不一致 | PC 端 `data\token.txt` 与 PDA `sync_state` 必须一致；改过 token 要重新配对 |
| **R9** | 一直显示「待传 N 条」不归零 | 上传一直失败 | 看 `sync_state.lastError`；PC 端 `logs\server.log`；先确认 R1–R5 |
| **R10** | PC 端条数比 PDA 少 | 有 `rejected` 的坏数据被跳过 | 看 `POST /scans` 响应的 `rejected` 明细 |
| **R11** | PC 端条数比 PDA **多** | 重复上传且 uid 不同（老数据缺 uid） | 检查 `scan_records.uid` 是否唯一非空 |
| **R12** | 删了的记录在 PC 还在 | 软删除没触发重传 | 确认 `softDelete*` 已改成 `syncedAt = NULL` |
| **R13** | 升级后 App 启动崩 | 迁移 SQL 与实体不一致 | `./gradlew :app:assembleDebug` 会报 Room schema 校验；也可能需要清滚（见 §5） |
| **R14** | 时间差 8 小时 | 时区处理错 | 传输一律带 `+08:00`；PDA 用 `SimpleDateFormat` 带 `XXX`；PC 端固定东八区 |
| **R15** | 二维码扫不出来 | 扫码枪只支持一维码 / 屏幕太小 | 用兜底手输 `ip:port#token`；或把 `pair.png` 放大到满屏 |

## 4. 数据对账（每天/每柜做一次）

```sql
-- PC 端：某柜收到多少条、多少正常
SELECT container_no, result, COUNT(*) FROM scans
WHERE deleted_at IS NULL AND container_no = 'ABCD1234567'
GROUP BY container_no, result;
```

对账口径：

| 项 | PDA（记录页/扫码页） | PC（SQL） |
| --- | --- | --- |
| 正常件数 | 计数卡「正常」 | `result='OK' AND deleted_at IS NULL` |
| 串号 | 计数卡「串号」 | `result='SERIAL_MISMATCH'` |
| 重复 | 计数卡「重复」 | `result='DUPLICATE'` |
| 超量 | 计数卡「超量」 | `result='OVER_LIMIT'` |
| 辅助码 | 计数卡「辅助」 | `result='AUX'` |

> 两边对不上时，**先查 `deleted_at`**（软删除会同时影响两边，但时间点可能差一轮同步）。

## 5. 回滚与降级

| 情况 | 回滚办法 |
| --- | --- |
| 同步功能影响现场扫码 | 设置页「解除配对」+ 关掉周期任务（或发一个 kill-switch 开关），**App 立即回到纯离线** |
| DB v14 迁移出问题 | 现场先从 `run-as` 快照 `zhuanggui.db`(含 -wal/-shm) 备份，再回退装 v1.7.5 旧包（旧包不认识 v14 → 需先卸载/清数据，**务必先备份**） |
| 服务端要停 | 直接停计划任务；PDA 侧只会「待传」堆着，不丢数据，恢复后自动补传 |

**降级开关**（强烈建议实现）：`sync_state` 里加 `enabled`，设置页可一键关同步 —— 出问题时先关掉，别让现场等排查。

---

## 6. 现场试运行前必须确认的 5 件事

1. PC 的 IP 是**固定**的（DHCP 保留或静态），否则每天要重新配对
2. PC **不休眠/不关机**（或至少工作时间不睡）：`powercfg /change standby-timeout-ac 0`
3. 防火墙规则已加，且网络配置文件是「专用」
4. 路由器**已关闭 AP 隔离**
5. PDA 已加入**电池优化白名单**（否则息屏后 15 分钟周期任务会被压制）

## 7. 验收通过标准（P0+P1）

- [ ] PDA 扫 100 条 → 断网 → 恢复 → PC 端 `SELECT COUNT(*)` = 100
- [ ] 连续触发同步 5 次 → PC 端仍是 100（幂等）
- [ ] 软删除 3 条 → 同步后 PC 端 `deleted_at IS NOT NULL` = 3
- [ ] 撤回那 3 条 → 同步后 `deleted_at IS NULL` 回到 100
- [ ] PC 端 `POST /tasks` 发 1 条 → PDA 同步 → 收件箱出现 → 装载后规则正确
- [ ] 现场机连续运行 1 天，`待传` 始终能归 0，无卡死
