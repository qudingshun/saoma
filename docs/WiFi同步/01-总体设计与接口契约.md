# WiFi 同步方案 · 01 总体设计与接口契约

---

## 1. 架构

```
┌──────────────────────────── 局域网（WiFi / 热点） ────────────────────────────┐
│                                                                              │
│   ┌──────────────── PDA (Android 11, com.zhuanggui.pda) ─────────────────┐   │
│   │  扫码页/设置页（现有，不改）                                          │   │
│   │        │ 每扫一码 → scan_records (uid, syncedAt=NULL)                 │   │
│   │        ▼                                                             │   │
│   │  SyncRepository ──(OkHttp)──┐                                        │   │
│   │        ▲                    │                                        │   │
│   │  SyncWorker (WorkManager)   │  POST /scans     上行（幂等）           │   │
│   │        │                    │  GET  /tasks     下行（增量）           │   │
│   │  Room: scan_records         │  POST /ack       游标确认               │   │
│   │        sync_inbox           │                                        │   │
│   │        sync_state           │                                        │   │
│   └─────────────────────────────┼────────────────────────────────────────┘   │
│                                 │                                            │
│   ┌─────────────────────────────▼──── Windows PC ────────────────────────┐   │
│   │  FastAPI (0.0.0.0:8000)                                              │   │
│   │    /api/v1/health   /tasks   /scans   /ack                           │   │
│   │        │                  │                                          │   │
│   │        ▼                  ▼                                          │   │
│   │   SQLite: tasks(rev)  scans(uid)  acks(deviceId)  devices            │   │
│   └──────────────────────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────────────────────┘
```

**数据流（正常一次装柜）**

1. PC 端录入/导入任务 → `POST /tasks`（服务端 rev+1）
2. PDA 定时或手动同步 → `GET /tasks?since=<lastTaskRev>` → 落 `sync_inbox`
3. 现场在 PDA 设置页点「装载收到的任务」→ 生成 `load_containers` + `load_rules`（走现有流程）
4. 扫码 → 现有逻辑写 `scan_records`（`syncedAt=NULL`）
5. `SyncWorker` 批量 `POST /scans` → 成功回写 `syncedAt`
6. `POST /ack` 告诉服务端"PDA 已消费到 rev=N"

## 2. 通用约定

| 项 | 约定 |
| --- | --- |
| Base URL | `http://<pc-ip>:<port>/api/v1` |
| 编码 | `Content-Type: application/json; charset=utf-8` |
| 鉴权 | 请求头 `X-Sync-Token: <token>`；`/health` 不校验 |
| 时间 | ISO8601 **带时区**，如 `2026-10-20T15:01:02.123+08:00`；PDA 落库转 epoch millis |
| 设备标识 | 头 `X-Device-Id: PDA-01`（首次启动生成并持久化，见 02 文档） |
| 版本 | 路径 `/api/v1`，服务端返回 `serverVer`；**不兼容变更才升 v2** |
| 分页 | `?limit=` 默认 200，最大 1000；返回 `hasMore` |
| 错误体 | `{"error":{"code":"...","message":"...","detail":"..."}}` |

### 错误码

| HTTP | code | 含义 | PDA 侧处理 |
| --- | --- | --- | --- |
| 400 | `BAD_REQUEST` | 参数不合法 | 记录日志，**不重试**（否则死循环） |
| 401 | `BAD_TOKEN` | token 不匹配 | 状态栏标红「配对失效」，提示重新扫码配对 |
| 413 | `TOO_LARGE` | 单批过大（>1000 条） | 拆小批量重试 |
| 409 | `REV_CONFLICT` | 下行 rev 冲突 | 重新拉全量（`since=0`） |
| 422 | `VALIDATION` | 字段校验失败 | 记录日志，跳过该条 |
| 500 | `SERVER_ERROR` | 服务端异常 | 指数退避重试 |
| — | 网络异常 | 连不上/超时 | 指数退避重试（30s→60s→120s→… 上限 30 分钟） |

## 3. 接口契约

### 3.1 `GET /api/v1/health`（免鉴权）

用途：PDA「测试连接」按钮；联调第一条命令。

**响应 200**

```json
{
  "ok": true,
  "serverVer": 1,
  "time": "2026-10-20T15:00:00.000+08:00",
  "dbPath": "E:\\saoma\\saoma-sync\\data\\sync.db",
  "pendingScans": 42
}
```

| 字段 | 说明 |
| --- | --- |
| `serverVer` | 协议版本，当前固定 `1` |
| `time` | 服务端当前时间（PDA 用它判断时钟偏差，>5 分钟提醒） |
| `pendingScans` | 已接收扫码记录总数（给现场一个"到底传上来没有"的直观数） |

---

### 3.2 `GET /api/v1/tasks?since=<rev>&limit=200`（下行）

PDA 拉取**装柜任务**的增量变更。

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `since` | int | 是 | PDA 已消费到的 rev；首次传 `0` |
| `limit` | int | 否 | 默认 200，最大 1000 |

**响应 200**

```json
{
  "serverVer": 1,
  "nextRev": 13,
  "hasMore": false,
  "tasks": [
    {
      "rev": 12,
      "containerNo": "ABCD1234567",
      "totalQuantity": 1200,
      "note": "10/20 夜班",
      "updatedAt": "2026-10-20T14:50:00.000+08:00",
      "deleted": false,
      "rules": [
        {
          "prefix": "ASV12",
          "allowDuplicate": false,
          "countEnabled": true,
          "checkHistory": false,
          "ignoreRepeat": false,
          "serialMin": "",
          "serialMax": "",
          "serialTailLen": 0
        }
      ]
    }
  ]
}
```

**字段约束**

| 字段 | 约束 |
| --- | --- |
| `containerNo` | 1–32 位，字母+数字（与 App 现有校验一致）；**全局唯一**，同柜号再推 = 更新 |
| `totalQuantity` | ≥ 0；`0` = 不限（与 `LoadContainer.totalQuantity` 语义一致） |
| `rules[].prefix` | 1–32 位字母+数字；同一 task 内不得重复 |
| `rules[].serialMin/Max` | 空串 = 该侧不限；非空必须是纯数字 |
| `rules[].serialTailLen` | ≥ 0；`0` = 旧语义（前缀后整段） |
| `deleted` | `true` = 该任务作废，PDA 应从 `sync_inbox` 里移除 |

**PDA 侧落地规则**

- 按 `containerNo` **REPLACE** 写入 `sync_inbox`（唯一索引）
- `serverRev` 写入 `sync_state.lastTaskRev = nextRev`
- **不触碰** `load_containers` / `load_rules`

### 3.3 `POST /api/v1/scans`（上行，幂等）

PDA 批量提交扫码记录。

**请求**

```json
{
  "deviceId": "PDA-01",
  "appVersion": "1.7.5",
  "scans": [
    {
      "uid": "8f14e45f-ceea-467f-9d1b-0f2c3a4b5d6e",
      "containerNo": "ABCD1234567",
      "barcode": "ASV12SDFWG05455056",
      "fullCode": "ABCD1234567，ASV12SDFWG05455056",
      "result": "OK",
      "scannedAt": "2026-10-20T15:01:02.123+08:00",
      "operatorId": "A",
      "deletedAt": null
    }
  ]
}
```

**`result` 取值**（必须与 App 枚举 `ScanResult` 完全一致）

```
OK | NOT_IN_LIST | OVER_LIMIT | SERIAL_MISMATCH | DUPLICATE | AUX
```

> `NOT_IN_LIST` 是历史语义，现在不会产生，但**允许**上传（保证老数据能回传）。

**响应 200**

```json
{
  "accepted": 1,
  "duplicated": 0,
  "rejected": [],
  "serverRevOut": 57,
  "serverTime": "2026-10-20T15:01:03.000+08:00"
}
```

| 字段 | 说明 |
| --- | --- |
| `accepted` | 新插入条数 |
| `duplicated` | 因 `uid` 已存在而跳过条数（**这是正常的**，不是错误） |
| `rejected` | 校验失败的明细：`[{"uid":"...","reason":"..."}]`；PDA 对这些**不重试**，只记日志 |
| `serverRevOut` | 服务端收到的总条数，便于对账 |

**幂等规则（关键）**

- 服务端以 `uid` 为唯一键：`INSERT OR IGNORE`
- **同一 uid 重复提交 → `duplicated++`，不报错**
- 因此 PDA 可以"传了不确定成功，再传一次"，永远不会翻倍

**PDA 侧成功判定**

- HTTP 200 且 `rejected` 里不含该 uid → 回写 `syncedAt = now`
- 有 `rejected` 的 uid → 也回写 `syncedAt`（避免死循环重传），但写入本地日志表

---

### 3.4 `POST /api/v1/ack`（游标确认）

PDA 告知服务端"我已处理到 rev=N"，用于服务端统计哪些 PDA 落后。

**请求**

```json
{ "deviceId": "PDA-01", "rev": 13, "appVersion": "1.7.5" }
```

**响应 200**

```json
{ "ok": true, "serverRev": 13 }
```

---

### 3.5 `GET /api/v1/stream?rev=<lastRev>`（P3 可选，SSE）

PDA 前台时保持长连接，PC 有新任务立刻推下来，实现"发完 3 秒内弹提示"。

```
Content-Type: text/event-stream

event: task
data: {"rev":14,"containerNo":"XYZ999","totalQuantity":600,...}

event: ping
data: {"t":"2026-10-20T15:10:00.000+08:00"}
```

- 每 30 秒发一次 `ping` 保活
- PDA 断线后回落为普通轮询，不依赖它保证正确性

> **可选**：不做 SSE 也不影响功能，PDA 用 WorkManager 每 15 分钟拉一次即可。

## 4. 配对（P0）

### 二维码内容（由 PC 生成并显示）

```
SAOMASYNC1|ip=192.168.1.100|port=8000|token=K7F2QW9M|ver=1
```

| 段 | 说明 |
| --- | --- |
| `SAOMASYNC1` | 前缀，PDA 用它校验"扫到的是配对码，不是商品条码" |
| `ip` / `port` | 服务端地址 |
| `token` | 8 位随机串（大小写字母+数字，去掉易混的 `0O1lI`） |
| `ver` | 协议版本 |

### PDA 侧配对流程

1. 设置页 → 「WiFi 同步」→ 「扫描配对码」
2. 用 PDA 扫码枪扫 PC 屏幕上的二维码
3. 校验前缀 → 解析出 `ip/port/token` → 立即调 `GET /health` 验证
4. 成功 → 写入 `sync_state`（`serverUrl`、`token`、`deviceId` 保留不变）；失败 → Toast 报错原因
5. **兜底**：`ip:port#token`（如 `192.168.1.100:8000#K7F2QW9M`）可手输

> ⚠️ 若现场扫码枪只支持一维码，二维码扫不出来 → 用兜底手输，**必须有这个入口**。

## 5. 增量与一致性规则

| 场景 | 规则 |
| --- | --- |
| PDA 首次同步 | `since=0` 拉全量任务 |
| 任务被作废 | PC 端置 `deleted=true`（rev+1）；PDA 收到后从 `sync_inbox` 删除 |
| 同柜号重复推送 | 服务端按 `containerNo` upsert，rev+1；PDA REPLACE 覆盖 |
| PDA 重装 App | `deviceId` 丢失 → 生成新 ID；旧记录已上传过的不会重传（`syncedAt` 在库里，重装即丢，但服务端按 `uid` 幂等，重传也无害） |
| 记录被软删/撤回 | PDA 把 `deletedAt` 变化的记录 **`syncedAt` 置 NULL** → 下次重新上传（服务端 UPSERT 更新 `deletedAt`） |
| 服务端 rev 回退（换库） | PDA 收到 `REV_CONFLICT` → 清空 `lastTaskRev` 重新全量拉 |
